# ITP HRM — тарификация, биллинг и лимиты

Дата: 2026-11-05. Ветка: feature/hrm-saas-enforcement-checkout-20261105.
Изоляция: исключительно база, API и frontend HRM, без влияния на Portal / ТОиР / Inventory.

## Безопасные флаги (исходно OFF)

    HRM_SAAS_REGISTRATION_ENABLED=false
    HRM_SAAS_BILLING_ENABLED=false
    HRM_SAAS_ENFORCEMENT_ENABLED=false

Ни один из флагов не включается автоматически при создании счетов/тарифов.
Даже при включении enforcement существующая компания без записи
hrm_company_legal_context не подвергается коммерческим ограничениям.
Старую компанию нельзя незаметно перевести на тариф просто назначением подписки.

## Реализованные сценарии

- Планы: version+SHA снимка условий, рубрикация сотрудников, лицензированные пользователи,
  активные HRM модули, пределы файлов и хранения; право доступа проверяет Laravel, не frontend.
- Модули: company-scoped middleware, включая personnel, staffing, vacations, worktime,
  documents, development, employees и роли; чтение кадровых данных остаётся возможным
  при окончании оплаченного периода. Новые мутации без оплаченной подписки запрещены.
- Количество пользователей: атомарная проверка при выдаче новой роли/доступа компании.
- Количество карточек сотрудников: атомарная проверка перед INSERT с блокировкой компании.
- Объём файлов: кадровые PDF, справки по отсутствиям, фотографии (photo_byte_size)
  включены в суммарный учёт 1 GiB. Размер каждого файла контролируется отдельно.
  Формат PDF и MIME/содержимое валидируются.
- Customer checkout: администратор организации оформляет счёт по опубликованному
  платному тарифу и сроку 1–120 месяцев; одинаковый неоплаченный счёт повторно не создаётся.
- Счёт: выставленные реквизиты и тарифная версия фиксируются в JSON snapshot;
  цены в KZT и указанный НДС рассматриваются как включенные в брутто, без двойного добавления.
- Настоящий PDF A4: Dompdf 3.1.6, шрифт DejaVu Sans, без удалённых ресурсов или JS.
  Доступ к PDF только администратора своей компании или оператора billing.read.
- Proof: PDF/JPG/PNG до 8 MiB с проверкой сигнатуры, SHA, закрытое хранилище,
  проверка компании и счёта. Дубликаты загрузки отклоняются.
- Оплата: уполномоченный оператор сверяет банковский reference и полную сумму,
  вводит причину, принимает или отклоняет загруженное доказательство.
  Оператор не может одобрить собственный загруженный файл.
- Подписка: только успешная сверка активирует платный доступ; повторная операция
  не активирует его дважды. Продление того же плана сохраняет предыдущие оплаченные дни.
  Смена активного тарифа требует отдельного расчёта, а не скрытого перерасчёта.
- Платёжные операции и назначение тарифа журналируются.
- UI: /hrm/admin/payments — счета и платёжные подтверждения,
  /hrm/billing — отдельный кабинет оплаты для админа компании, включая
  счёт, PDF, подтверждения, тарифные лимиты и индикатор использования.

## Защищённые маршруты API

Все пути имеют префикс /api/v1.
Компания: GET /companies/{company}/billing/subscription
GET /companies/{company}/billing/invoices
POST /companies/{company}/billing/checkout
GET /companies/{company}/billing/invoices/{invoice}/pdf
GET/POST /companies/{company}/billing/invoices/{invoice}/proofs
GET /companies/{company}/billing/invoices/{invoice}/proofs/{proof}/file

Платформа: GET /platform-admin/invoices/{invoice}/pdf,
GET/POST /platform-admin/invoices/{invoice}/proofs,
POST /platform-admin/invoices/{invoice}/proofs/{proof}/review.

Оформление счёта и загрузка файла НЕ означают успешную оплату.
Банковский референс уникален среди оплаченных счетов и должен быть подтверждён
ПО ВНЕШНЕЙ банковской выписке уполномоченным оператором.
Прямой автоматической банковской интеграции ещё нет.

## Известные границы

- Сверка денег ручная, нет банка/webhook, ЭЦП и ERP/1C-обмена.
- Нет массовой автоматической отправки PDF email, нужно проверить SMTP.
- PDF генерируется из снимка условий при скачивании; архивный PDF-файл
  и отдельный юридический SHA/подпись на выпуске ещё не сохраняются.
- Для иных будущих вложений потребуется централизованный реестр хранилища.
- Действующие специальные формы могут иметь ограничение 5 MiB при общем
  лимите тарифа 35 MiB; это более строгое локальное ограничение.
- Тесты PHPUnit в SQLite не заменяют тесты реальных блокировок PostgreSQL.
- Сервер production и ветка main в данном проходе не изменялись.
